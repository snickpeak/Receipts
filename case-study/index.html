Problem Statement

Journaling apps are built for the wrong thing

Most journaling apps optimize for streaks, sharing, and engagement. They turn private reflection into a performance metric. Receipts was built to solve a different problem entirely.

People lose track of their own story. Wins get forgotten. Promises fade. The moments that shaped you disappear into your camera roll or the back of your mind. There's no focused, private place to keep receipts on what you did, what was said, and what you've built — until now.

Features

📝

TF-IDF ranked search across all entries — keyword and semantic, fully on-device.

Tech Stack

Decisions made for the long term

Every technology choice was made to maximize developer velocity, minimize third-party dependencies, and keep user data on-device wherever possible.

Layer Technology Why
Language TypeScript 5.9 Strict mode throughout — catches bugs at compile time, not runtime.
Framework React Native 0.81.5 Native performance, cross-platform reach, large ecosystem.
SDK Expo 54 (New Architecture) Managed workflow with new architecture enabled for JSI performance.
Navigation Expo Router 6 File-based routing — predictable, typesafe, deep-link ready.
Auth Clerk Full auth system without building session management from scratch.
Data Fetching TanStack Query v5 Server state, caching, and optimistic updates out of the box.
Animations React Native Reanimated 4 UI thread animations — no JS bridge, 60fps guaranteed.
Build EAS Build + EAS Submit Cloud builds, auto-submit to TestFlight, no local Xcode required.
Compiler React Compiler (experimental) Automatic memoization — eliminates manual useMemo/useCallback.

SDLC Process

From concept to App Store

This project was built end-to-end — product definition, architecture, development, release pipeline, and App Store compliance.

Discovery

Problem definition and scope

Identified the gap in the journaling market — existing apps optimize for engagement over privacy. Scoped MVP around private capture, search, and retrieval. Defined core tag taxonomy (Win, Money, Memory, Promise, Proof) as the organizational backbone.

Architecture

Stack selection and system design

Chose Expo for managed workflow and fast iteration. File-based routing via Expo Router for maintainable navigation. Clerk to avoid building custom auth. TanStack Query for server state with optimistic updates. Designed offline-first data model from day one.

Development

Vertical slices, ship early

Built in priority order: auth flow → core entry CRUD → search and calendar → advanced features (OCR, voice memos, geolocation, biometric lock, threads). TypeScript strict mode throughout. React Compiler enabled for automatic performance optimization.

Quality

Static analysis and device testing

TypeScript compiler as primary static analysis gate. Tested on physical iPhone hardware via Expo Go and development builds. Reduce Motion accessibility support throughout all animations. Validated biometric, OCR, and location flows on-device.

Release

EAS Build pipeline + TestFlight

EAS Build configured with development, preview, and production profiles. Production iOS builds auto-submitted to TestFlight via eas build --auto-submit. Android EAS Submit configured for Google Play internal track.

Compliance

Apple Privacy Manifest and App Store review

Completed Apple Privacy Manifest for all accessed API categories. Permission strings written for Face ID, camera, microphone, and location. Declared no exempt encryption. No third-party analytics or ad SDKs included. App Store metadata, screenshots, and keywords prepared for submission.
